# 급여명세서 자동 발송 시스템

세무사로부터 매달 받는 직원별 임금명세서 PDF를, 각 직원 본인에게 Outlook으로
안전하게 자동 발송하는 사내 도구입니다.

- 최종 사용자: 대표님(비개발자) — 파이썬 없이 `.exe` 더블클릭 실행
- 발송: 매월 급여 지급일(5일)의 2~3일 전

---

## 1. 무엇이 안전한가 (설계 핵심)

이 회사 명세서에는 **사번이 없습니다.** 라벨이 `생년월일(사번)`이며,
**생년월일 6자리가 곧 식별자이자 PDF 열람 비밀번호**입니다.
하나의 값이 두 역할을 하므로, 이를 이용해 사고를 구조적으로 막습니다.

**발송 조건 = 3중 교차검증**
아래 세 값이 **명부의 한 행과 모두 일치**할 때만 발송합니다.

1. PDF 본문의 생년월일 (= 비밀번호)
2. PDF 본문의 성명
3. 파일명의 성명 (`임금명세서_이름_.pdf`)

→ 비밀번호(생년월일)가 다른 사람 것으로 잘못 걸리는 사고가 **구조적으로 불가능**합니다.
하나라도 어긋나거나 후보가 0명/2명 이상이면 그 건은 **발송에서 제외**되고 빨간색으로 표시됩니다.

## 2. 사용 순서 (대표님용)

1. **상위 폴더 지정** — 월별 폴더(`202607` 등)들이 들어 있는 부모 폴더
2. **명부 지정** — `생년월일 / 이름 / 이메일` 컬럼이 있는 `mapping.xlsx`
3. **폴더 확인** — 대상 월 폴더에 PDF가 몇 개 있는지 확인
4. **① 계획 미리보기** — 누가 무엇을 받는지 **표로** 확인 (발송 안 함)
   - 🟩 초록 = 정상 / 🟨 노랑 = 확인 필요(귀속월 다름·이미 발송됨) / 🟥 빨강 = 발송 불가
   - 행을 **더블클릭**하면 사유를 자세히 볼 수 있습니다.
5. **② 선택한 직원에게 발송** — 표에서 **체크된 직원에게만** 발송

> 💡 처음에는 **테스트 수신자**에 본인 메일을 넣고 한 번 시험해 보세요.
> 그때는 모든 메일이 본인에게만 갑니다.

## 3. 편의 기능

| 기능 | 설명 |
|------|------|
| **표(Treeview)로 계획 표시** | `파일명·이름·생년월일·이메일·귀속월·상태`. 문제 행이 한눈에 색으로 보임 |
| **체크박스 개별 선택 발송** | 특정 직원만 빼거나, 실패한 1명만 고쳐 재발송 가능 |
| **발송 이력 로그** | `발송기록_YYYYMM.csv`에 기록. 이미 보낸 건은 다음 실행 때 **자동 체크 해제**(중복 방지) |
| **명부 검증 버튼** | 이메일 오류·생년월일 6자리 아님·중복 생년월일·빈칸을 미리 점검 |
| **메일 문구 편집** | `template.txt`를 GUI에서 수정. `{이름}`, `{귀속월}` 치환. 코드 수정 불필요 |
| **초안 모드** | `.Send()` 대신 `.Display()`로 초안만 띄우고 직접 발송 |
| **대상 월 드롭다운** | 상위 폴더의 `YYYYMM` 폴더를 자동 스캔해 목록 제시(오타 방지) + PDF 개수 표시 |
| **진행률 바** | 암호화·발송이 몇 명 중 몇 명인지 실시간 표시 |
| **우클릭 메뉴** | 행에서 우클릭 → **"이 사람만 발송"**(실패 1명 재발송이 빠름) / 체크 / 상세 |
| **문제만 보기 필터** | 경고·실패 행만 추려서 보기. 미리보기 후 첫 문제 행으로 자동 이동 |
| **바로가기** | 대상 폴더 열기 / 발송기록(CSV) 열기 버튼 |
| **상태 유지** | 창 크기·초안모드·마지막 대상 월까지 기억. `F5`=미리보기 |

## 4. 명부(mapping.xlsx) 형식

| 컬럼 | 필수 | 설명 |
|------|:---:|------|
| `생년월일` | ✅ | 6자리(YYMMDD). 식별자이자 PDF 비밀번호 |
| `이름` | ✅ | 본문·파일명과 대조 |
| `이메일` | ✅ | 수신 주소 |
| `비밀번호` | 선택 | 회사가 별도 비번을 지정할 때만. **비어 있으면 생년월일 사용** |

예시 파일: [`mapping_예시.xlsx`](mapping_예시.xlsx) (가상 데이터)

> ⚠️ 실제 명부(`mapping.xlsx`)와 PDF, 발송기록은 **개인정보**이므로
> 저장소에 올라가지 않도록 `.gitignore`에 등록돼 있습니다.

## 5. 개발자용 (유지보수)

### 구조
```
payroll_core.py   ← 매칭/파싱/암호화/명부검증/로그/템플릿 (tkinter·win32 비의존, 단독 테스트 가능)
payroll_gui.py    ← Tkinter GUI (payroll_core 사용)
payroll_sender.py ← CLI 참고용 (payroll_core 공유)
test_core.py      ← 회귀 테스트
template.txt      ← 메일 문구
```

### 설치 / 테스트
```bash
pip install pywin32 pdfplumber pandas openpyxl pypdf cryptography
python test_core.py <샘플PDF경로>      # 세무사 포맷이 바뀌면 여기부터 확인
```

### .exe 빌드

> ⚠️ **exe는 반드시 Windows에서 빌드해야 합니다.**
> PyInstaller는 크로스 컴파일을 지원하지 않아, Linux/Mac에서 빌드하면
> 해당 OS용 바이너리가 나옵니다. 게다가 이 앱은 `win32com`(Outlook)에 의존합니다.

**방법 A — GitHub Actions에서 자동 빌드 (권장, 윈도우 PC 불필요)**

이 저장소에 푸시하면 [`.github/workflows/build-exe.yml`](.github/workflows/build-exe.yml)이
Windows 러너에서 자동으로 빌드합니다.

1. GitHub 저장소 → **Actions** 탭 → **exe 빌드** 워크플로 선택
2. 최신 실행 결과 클릭 → 하단 **Artifacts**에서 `급여명세서발송기-windows` 다운로드
3. 압축을 풀면 `급여명세서발송기.exe` + `template.txt` + `mapping_예시.xlsx` + `README.md`

수동 실행은 Actions 탭의 **Run workflow** 버튼으로도 가능합니다.

**방법 B — 윈도우 PC에서 직접 빌드**

[`빌드.bat`](빌드.bat)을 **더블클릭**하면 패키지 설치 → 로직 점검 → 빌드까지 자동 진행됩니다.
결과물은 `dist\급여명세서발송기.exe`.

직접 명령으로 하려면:
```bat
pip install -r requirements.txt pyinstaller
pyinstaller --onefile --windowed --name PayrollSender ^
    --hidden-import win32timezone --collect-data pdfminer payroll_gui.py
ren dist\PayrollSender.exe 급여명세서발송기.exe
```
- `--hidden-import win32timezone` : pywin32 빌드 시 누락되는 모듈
- `--collect-data pdfminer` : pdfplumber가 쓰는 pdfminer cmap 데이터 포함
- 빌드 이름을 ASCII(`PayrollSender`)로 잡고 나중에 바꾸는 이유는, PyInstaller에
  비ASCII `--name`을 주면 환경에 따라 실패하는 경우가 있기 때문입니다.

`config.json` / `template.txt` / `발송기록_*.csv`는 `sys.frozen` 여부에 따라
**exe 옆 경로**에 저장됩니다. 대표님 PC로는 **exe 하나만** 옮겨도 동작합니다
(`template.txt`는 첫 실행 시 자동 생성).

### 검증된 파싱 패턴 (payroll_core.py)
| 필드 | 정규식 |
|------|--------|
| 성명 | `성\s*명\s*:\s*([가-힣]{2,5})` |
| 생년월일 | `생년월일\s*\(\s*사번\s*\)\s*:\s*(\d{6})(?:\s*\(\s*(\d+)\s*\))?` |
| 지급일 | `지\s*급\s*일\s*:\s*([\d.]+)` |
| 귀속월 | `(\d{4})\s*년\s*(\d{2})\s*월분` |

## 6. 기술 제약 / 개인정보 원칙

- Outlook은 **데스크톱 앱 COM(win32com)** 방식. 실행 PC에 로그인된 계정으로 발송.
  **웹 전용 Outlook 환경은 지원하지 않습니다.**
- 스레드에서 COM 호출 시 `pythoncom.CoInitialize()` / `CoUninitialize()` 사용.
- **전 과정 로컬 처리.** 외부 API·클라우드로 원본을 전송하지 않습니다.
- **로그에 급여 금액·생년월일 전체를 남기지 않습니다.**
  (안내 문구의 생년월일은 `9301**` 형태로 마스킹)

## 7. 확인이 필요한 열린 질문

샘플이 1건뿐이라 아래는 **여러 직원 파일 확보 후** 확인이 필요합니다.
(현재 설계는 아래가 어떻든 안전하도록 방어적으로 동작합니다.)

- `생년월일(사번)` 뒤 괄호 숫자(예: `930124(48)`의 `48`)의 의미 —
  현재는 참고용으로만 추출. 고유값으로 확인되면 동명이인+동일 생년월일 충돌을
  완전히 없애는 4번째 자물쇠로 승격 가능.
- 동명이인 / 생년월일 중복 존재 여부 — 명부 검증 버튼이 중복을 잡아냄.
- 세무사가 매달 파일명 규칙(`임금명세서_이름_.pdf`)을 지키는지 —
  규칙에서 벗어나면 파일명 성명 확인 실패로 안전하게 걸러짐.
